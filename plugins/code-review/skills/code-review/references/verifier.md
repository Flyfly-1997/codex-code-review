## 怎么查
- 阅读包：{{PACKS}}。**只读候选引用的行与其所在函数**，不读整个文件；包被截断时才 `read` 仓库文件。
- **必须自己重读代码**再判断；不要仅凭候选给的描述下结论。
- **≤ 15 次工具调用 / ≤ 5 条消息**。
- 对 `guidelines`：确认被引用的规则确实覆盖这个文件，且代码确实违反。
- 对 `bug`：确认失败路径，而不只是"形迹可疑"。
- 行为候选亲自读实际入口，核对操作、有效输入或状态、变更后的分支和可见结果。跨前后端确认客户端真正送出的值与后端假设相同。匹配和状态机分别核对选择、状态推进、校验、回退或清理；区分拒绝、超时和异常。只知道函数接受构造出的输入时填 `trigger: unproven`，用 `cannot-verify`。已读代码直接排除该路径时可 `rejected`，并说明哪个入口或守卫排除它。仓库规范和纯可维护性填 `not-applicable`。
- 对"注释/文档里写了锁、顺序、事务、归属不变量"的候选：先确认该不变量，再按危害定档——事务内取第二个连接、锁跨无关 await，属于**高**。

## 置信度评分（对"缺陷是否真实"，不是严重度、稀有度、影响）
- **0** — 基本是误报，或属于既有问题
- **25** — 可能；失败路径未能确认
- **50** — 形似真实，但失败路径或违反的契约没钉死
- **75** — 高度确信：重读后确认缺陷存在，且是本次改动造成的——**即使它罕见、窄、影响小**
- **100** — 绝对确定：有具体的一步步失败路径，或代码明显产出错误结果

⚠ **稀有 ≠ 可疑**：需要罕见输入、亚秒竞态、网络失败的缺陷仍是 75–100；本次改动让某条注释/类型契约变成假话，也是 75。只有当你不确定缺陷本身是否真实时才降分。

## 严重度（三档）
- **high** — 现在的代码就会伤害真实用户：错误结果、数据/状态丢失、安全或隐私、崩溃、功能不可达、既有修复回归、明确违反书面规范；结构性风险（事务内取第二个连接、锁顺序反转、锁内无界重试）也算 high。
- **medium** — 需特定条件才出现的用户可见错误（丢更新竞态、某模式给下游"什么都不给"、文案与实际相反），或本次引入的热路径成本（每轮全量下载、列表查询新增扫描）。
- **low** — 约定漂移、冷路径 N+1、重复逻辑、过时注释、命名。

"既定行为"只豁免行为本身，不豁免它的副作用（例如删行是既定设计，但版本归零导致别人旧页面静默覆盖，是独立后果）。
